# UDP 远程终端

基于 UDP 协议实现的可靠远程终端程序，在应用层通过自定义协议和停等 ARQ 机制补齐基础可靠传输能力。

## 基础功能完成情况

本项目当前按《基于UDP的远程终端实验指导书.md》3.1 基础功能完成以下内容：

- [x] UDP 基础通信：客户端可指定服务端 IP 和端口，服务端绑定端口接收 UDP 报文。
- [x] 自定义协议封包/解包：校验魔数、类型、序列号、客户端 ID 和数据长度，非法报文直接丢弃。
- [x] 停等 ARQ 可靠传输：发送后等待 ACK，超时重传，使用序列号去重和保序。
- [x] 基础终端命令执行：支持非交互式命令执行，并将 stdout/stderr 返回客户端显示。
- [x] 基础控制字符处理：支持 `\n`、`\r`、`\b`、`\x7f` 的命令输入规范化。
- [x] 多客户端支持：服务端按客户端 ID 维护独立会话状态，避免客户端之间输出混乱。
- [x] 心跳检测：客户端每 5 秒发送心跳，服务端打印心跳日志并回复 ACK，约 30 秒无心跳则清理离线客户端。
- [x] SSH 风格提示符：客户端输入前显示 `[user@host dir]$` 格式的命令提示符。
- [x] 基本异常处理：命令不存在、服务端不可达、网络超时、非法报文等场景不会导致程序崩溃。

## 支持的命令

客户端输入的命令会直接在服务端执行，然后返回命令输出。基础版本适合执行非交互式、能在有限时间内结束的命令。

| 操作系统 | 常用命令示例 |
|---|---|
| Windows | `dir`、`cd`、`ipconfig`、`echo`、`tasklist`、`netstat`、`type` |
| Linux/macOS | `ls`、`pwd`、`ip addr`、`ifconfig`、`echo`、`ps`、`netstat`、`cat`、`df` |

注意事项：

- `cd` 命令只影响服务端执行该命令的子进程，不会改变服务端程序的全局工作目录。
- 不支持需要交互输入的命令，例如 `vim`、Python 交互式解释器、`sudo`、`rm -i` 等。
- 持续运行并持续输出的命令不保证实时回显；基础版本会在命令结束后返回输出。
- Windows 上建议使用 `dir`，Linux/macOS 上建议使用 `ls`。

## 使用方法

### 启动服务端

```bash
python server.py [端口]
```

默认监听 `0.0.0.0:9999`。例如：

```bash
python server.py 10000
```

也可以指定监听地址：

```bash
python server.py 10000 --host 0.0.0.0
```

### 启动客户端

```bash
python client.py [服务端IP] [服务端端口]
```

默认连接 `127.0.0.1:9999`。例如：

```bash
python client.py 192.168.1.100 10000
```

客户端会在输入前显示类似 `[user@host dir]$` 的提示符，其中 `user` 使用本机用户名，`host` 使用连接的服务端地址，`dir` 只显示客户端当前文件夹名；普通用户使用 `$`，root/Administrator 使用 `#`。

每次命令输出结束后，服务端会发送一个空输出报文作为结束标记，客户端收到后自动显示下一条提示符，不需要额外再按一次回车。

客户端中输入 `exit` 可以退出。`Ctrl+C` 不用于退出客户端；在提示符处按下时会像 SSH 一样显示 `^C` 并回到提示符，在命令执行期间按下时会发送远程中断报文并继续等待命令输出结束。

## 协议格式

固定头部 13 字节，采用大端字节序，单个 UDP 报文总长度控制在 1472 字节以内以避免 IP 分片。

| 字段 | 长度 | 说明 |
|---|---:|---|
| 魔数 | 2B | 固定 `0x5554`，用于识别合法报文 |
| 报文类型 | 1B | `0x01` 命令输入，`0x02` 命令输出，`0x03` ACK，`0x04` 心跳 |
| 序列号 | 4B | 停等 ARQ 序列号，用于 ACK、去重和保序 |
| 数据长度 | 2B | 数据段长度 |
| 客户端 ID | 4B | 区分多个客户端 |
| 数据段 | 可变 | 命令内容或输出内容 |

当前实现中，普通命令和输出序列号使用 `0..0xFFFFFFFE` 循环递增，`0xFFFFFFFF` 保留给心跳报文使用。

## 停等 ARQ 机制

- 发送端发送一个命令或输出分片后等待 ACK。
- 超过等待时间未收到 ACK 时重传。
- 超过最大重传次数后提示服务端不可达或网络中断。
- 接收端使用序列号判断是否为期望报文，重复报文只回复 ACK，不重复执行命令或重复显示输出。
- 输出超过单个数据段大小时按 `MAX_DATA_SIZE` 分块发送，每个分块独立确认。
- 服务端在一次命令输出发送完毕后额外发送空输出报文，客户端用它判断输出结束并刷新下一条提示符。

## 测试说明

运行自动化测试：

```bash
python test_all.py
```

测试覆盖内容包括：

- 协议封包/解包、魔数校验、类型校验、长度校验、超长数据拒绝。
- 4 字节序列号、ACK、超时重传和重复序列号去重。
- 命令执行和输出显示。
- 多客户端隔离。
- 心跳 ACK、服务端心跳日志和离线清理。
- 基础控制字符 `\n`、`\r`、`\b`、`\x7f` 处理。
- 命令不存在、服务端不可达、非法报文不崩溃等异常场景。

## 进阶功能说明

本项目当前重点完成实验指导书 3.1 基础功能，以下内容不作为基础功能验收范围：

- 实时命令输出。
- 回退 N 步 ARQ 或滑动窗口流量控制。
- PTY 伪终端和终端窗口大小同步。
- `top`、`vim` 等全屏交互式程序。
- 远程 Ctrl+C 中断属于进阶控制字符能力，客户端已不再用 Ctrl+C 退出，并保留中断报文发送入口，但未作为基础功能测试项。
