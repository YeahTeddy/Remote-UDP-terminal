# UDP 远程终端

基于 UDP 协议实现的可靠远程终端程序，在应用层通过自定义协议和停等 ARQ 机制补齐基础可靠传输能力。

## 基础功能完成情况

本项目当前完成以下内容：

- [x] UDP 基础通信：客户端可指定服务端 IP 和端口，服务端绑定端口接收 UDP 报文。
- [x] 自定义协议封包/解包：校验魔数、类型、序列号、客户端 ID 和数据长度，非法报文直接丢弃。
- [x] 停等 ARQ 可靠传输：发送后等待 ACK，超时重传，使用序列号去重和保序。
- [x] 基础终端命令执行：支持非交互式命令执行，支持每个客户端独立持久的 `cd` 目录切换，并将 stdout/stderr 返回客户端显示。
- [x] 基础控制字符处理：支持 `\n`、`\r`、`\b`、`\x7f` 的命令输入规范化。
- [x] 远程 Ctrl+C 中断：命令执行期间按 Ctrl+C 会发送中断报文，服务端中断或清理当前命令进程树；提示符处 Ctrl+C 不退出客户端。
- [x] 多客户端支持：服务端按客户端 ID 维护独立会话状态，避免客户端之间输出混乱。
- [x] 心跳检测：客户端每 5 秒发送心跳，服务端打印心跳日志并回复 ACK；客户端约 2 秒未收到心跳 ACK 会提示连接异常并退出，服务端约 30 秒无心跳则清理离线客户端。
- [x] SSH 风格提示符：客户端输入前显示 `[user@host dir]$` 格式的命令提示符。
- [x] 基本异常处理：命令不存在、服务端不可达、网络超时、非法报文等场景不会导致程序崩溃。

## 支持的命令

客户端输入的命令会直接在服务端执行，然后返回命令输出。当前版本适合执行非交互式、能在有限时间内结束的命令。

| 操作系统 | 常用命令示例 |
|---|---|
| Windows | `dir`、`cd`、`ipconfig`、`echo`、`tasklist`、`netstat`、`type` |
| Linux/macOS | `ls`、`pwd`、`ip addr`、`ifconfig`、`echo`、`ps`、`netstat`、`cat`、`df` |

注意事项：

- `cd` 是服务端内置命令，会更新当前客户端自己的远端工作目录；后续命令都会在该目录下执行，不会影响其他客户端。
- 不支持需要交互输入的命令，例如 `vim`、Python 交互式解释器、`sudo`、`rm -i` 等。
- 持续运行并持续输出的命令不保证实时回显；当前会在命令结束、被中断或超时后返回输出。
- 普通命令最长执行约 30 秒；超时后服务端会清理当前命令进程树并返回超时提示。
- Windows 上建议使用 `dir`，Linux/macOS 上建议使用 `ls`。

## 使用方法

### 启动服务端

```bash
python server.py [端口]
```

默认监听 `0.0.0.0:9999`。例如：

```bash
python server.py 10000
```

也可以指定监听地址：

```bash
python server.py 10000 --host 0.0.0.0
```

### 启动客户端

```bash
python client.py [服务端IP] [服务端端口]
```

默认连接 `127.0.0.1:9999`。例如：

```bash
python client.py 192.168.1.100 10000
```

客户端启动后会先发送心跳并等待服务端 ACK；如果约 2 秒内没有收到回复，会打印连接失败并直接退出。连接成功后才会显示类似 `[user@host dir]$` 的提示符，其中 `user` 和 `host` 来自服务端，`dir` 根据服务端当前工作目录提取显示。普通用户使用 `$`，root/Administrator 使用 `#`。

每次命令输出结束后，服务端会发送一个携带当前工作目录的结束标记，客户端收到后自动更新提示符并显示下一条提示符，不需要额外再按一次回车。

客户端中输入 `exit` 可以退出。交互式终端中客户端只把 `exit` 作为主动退出命令；`Ctrl+C` 不用于退出客户端，在提示符处按下时会回到提示符，在命令执行期间按下时会发送远程中断报文并继续等待命令输出结束。Linux/macOS TTY 通常由终端回显 `^C`，客户端只补换行；Windows 或非 TTY 环境由客户端打印 `^C`。

## 协议格式

固定头部 13 字节，采用大端字节序，发送端将单个 UDP 报文总长度控制在 1472 字节以内以避免 IP 分片。

| 字段 | 长度 | 说明 |
|---|---:|---|
| 魔数 | 2B | 固定 `0x5554`，用于识别合法报文 |
| 报文类型 | 1B | `0x01` 命令输入，`0x02` 命令输出，`0x03` ACK，`0x04` 心跳，`0x05` 中断 |
| 序列号 | 4B | 停等 ARQ 序列号，用于 ACK、去重和保序 |
| 数据长度 | 2B | 数据段长度 |
| 客户端 ID | 4B | 区分多个客户端 |
| 数据段 | 可变 | 命令内容、输出内容或控制元信息 |

当前实现中，普通命令和输出序列号使用 `0..0xFFFFFFFE` 循环递增，`0xFFFFFFFF` 保留给心跳报文使用。中断报文用于通知服务端中断当前命令，不参与命令序列去重。

## 停等 ARQ 机制

- 发送端发送一个命令或输出分片后等待 ACK。
- 超过等待时间未收到 ACK 时重传。
- 超过最大重传次数后提示服务端不可达或网络中断。
- 接收端使用序列号判断是否为期望报文，重复报文只回复 ACK，不重复执行命令或重复显示输出。
- 输出超过单个数据段大小时按 `MAX_DATA_SIZE` 分块发送，每个分块独立确认。
- 服务端在一次命令输出发送完毕后额外发送结束标记，客户端用它判断输出结束并同步远端当前目录。
- 心跳 ACK 会携带服务端用户名、主机名和当前目录，客户端用它初始化提示符。

## 测试说明

运行自动化测试：

```bash
python test_all.py
```

自动化测试和实现验证内容包括：

- 协议封包/解包、魔数校验、类型校验、长度校验、超长数据拒绝。
- 4 字节序列号、ACK、超时重传和重复序列号去重。
- 命令执行、持久 `cd` 目录切换和输出显示。
- 多客户端隔离。
- 心跳 ACK、客户端启动连接判定、提示符元信息同步、服务端心跳日志和离线清理。
- 基础控制字符 `\n`、`\r`、`\b`、`\x7f` 处理。
- 命令不存在、服务端不可达、非法报文不崩溃等异常场景。

自动化测试不模拟交互式终端 Ctrl+C；如需验证远程中断，可手动运行 `ping`、`sleep` 等长命令后按 Ctrl+C。

## 进阶功能说明

除当前已实现的远程 Ctrl+C 中断外，以下进阶内容不作为基础功能验收范围：

- 实时命令输出。
- 回退 N 步 ARQ 或滑动窗口流量控制。
- PTY 伪终端和终端窗口大小同步。
- `top`、`vim` 等全屏交互式程序。
- 更完整的终端控制字符和作业控制能力。

## 进阶功能实现说明

在保留上述基础实现的基础上，当前版本追加完成了实验指导书 3.2 中的进阶功能，不包含 3.3 拔高功能：

- [x] 终端控制字符增强：保留已实现的远程 Ctrl+C 中断；命令输入继续正确处理换行、回车、退格和 Delete；Tab 会作为命令字符传递给远端 shell，不在客户端改写为空格，也不实现远端补全；输入和输出中的 ANSI 转义序列会被过滤，避免显示乱码。
- [x] 输出方向滑动窗口可靠传输：客户端到服务端的命令输入仍使用停等 ARQ；服务端到客户端的命令输出改为小窗口批量发送，按分片序列号确认、超时重传，并在客户端按序缓冲和显示，提升大批量输出传输效率。
- [x] 实时命令输出：服务端执行命令时会持续读取 stdout/stderr 并立即发送给客户端，适合 `ping` 或逐行 flush 的持续输出命令，不再等待命令完全结束后一次性返回。

进阶功能限制：

- 本项目没有引入 PTY，因此部分程序在检测到 stdout/stderr 是管道时可能自行缓冲输出；已 flush 的输出会实时传输。
- Tab 不等同于 SSH 里的远端补全能力；由于本项目执行的是单条非交互式命令，Tab 仅作为 shell 可识别的空白/控制字符透传。
- 仍不支持 `vim`、`top`、交互式 Python、`sudo` 提示输入等需要完整交互终端的程序。
- 不实现终端窗口大小同步，也不实现按接收端缓冲区动态调整窗口的流量控制。

新增进阶验证项：

- `python test_all.py` 会额外验证 ANSI 过滤、Tab 透传、实时输出首包提前到达，以及大输出滑动窗口传输完整性。
- 手动验证实时输出可执行：`python -c "import time; print('one', flush=True); time.sleep(2); print('two', flush=True)"`。
- 手动验证 ANSI 过滤可执行：`python -c "print('\\033[31mRED_TEXT\\033[0m')"`。
