# UDP 远程终端

基于 UDP 协议实现的可靠远程终端程序。项目按实验指导书要求先完成基础远程命令执行能力，再在基础实现上追加实时输出、输出方向滑动窗口可靠传输、控制字符增强等进阶功能；当前不包含 PTY、终端窗口大小同步、`top`/`vim` 全屏交互等拔高功能。

## 一、基础功能部分

### 1.1 已实现功能与实现方法

| 基础功能 | 实现方法 |
|---|---|
| UDP 基础通信 | 客户端可指定服务端 IP 和端口；服务端绑定 UDP 端口并循环接收报文。 |
| 自定义协议封包/解包 | 统一使用固定 13 字节头部，包含魔数、报文类型、序列号、数据长度、客户端 ID；非法魔数、非法类型、长度不匹配报文会被直接丢弃。 |
| 基础可靠传输 | 使用 ACK、超时重传、序列号去重和保序机制补齐 UDP 不可靠问题；当前命令输入方向仍使用停等 ARQ。 |
| 基础命令执行 | 服务端按客户端提交的命令启动子进程执行，捕获 stdout/stderr 后通过 UDP 返回客户端；Windows 下按字符串交给系统 shell 执行，兼容 `python -c "..."` 这类带双引号的命令，Linux/macOS 下使用 `bash -c` 执行。 |
| 持久 `cd` | `cd` 由服务端内置处理，不启动外部子进程；每个客户端维护独立 `cwd`，后续命令会在该目录下执行。 |
| 基础控制字符处理 | 命令输入会规范化 `\n`、`\r`、退格 `\b`、Delete `\x7f`，避免用户输入中的基础控制字符破坏命令内容。 |
| 多客户端支持 | 服务端按客户端 ID 维护独立会话状态，包括地址、心跳时间、收发序列号、当前工作目录和当前执行进程。 |
| 心跳检测 | 客户端每 5 秒发送心跳；服务端收到心跳后回复 ACK；客户端约 2 秒未收到心跳 ACK 会提示连接异常并退出，服务端约 30 秒无心跳则清理离线客户端。 |
| SSH 风格提示符 | 心跳 ACK 携带服务端用户名、主机名和当前目录；客户端显示 `[user@host dir]$` 或 `[user@host dir]#` 格式提示符。 |
| 基本异常处理 | 命令不存在、服务端不可达、网络超时、非法报文等场景不会导致程序崩溃。 |

### 1.2 基础阶段支持的命令

基础阶段适合执行**非交互式、能在有限时间内结束**的命令。

| 操作系统 | 常用命令示例 |
|---|---|
| Windows | `dir`、`cd`、`ipconfig`、`echo`、`tasklist`、`netstat`、`type` |
| Linux/macOS | `ls`、`pwd`、`ip addr`、`ifconfig`、`echo`、`ps`、`netstat`、`cat`、`df` |

说明：

- `cd` 是服务端内置命令，会更新当前客户端自己的远端工作目录，不影响其他客户端。
- 客户端中输入 `exit` 用于退出客户端，不会发送到服务端执行。
- 普通命令最长执行约 30 秒；超时后服务端会清理当前命令进程树并返回超时提示。
- 基础阶段不支持需要交互输入的命令，例如 `vim`、Python 交互式解释器、`sudo`、`rm -i` 等。

## 二、进阶功能部分

### 2.1 已实现功能与实现方法

| 进阶功能 | 实现方法 |
|---|---|
| 远程 Ctrl+C 中断 | 客户端在命令执行期间捕获 Ctrl+C，发送中断报文；服务端记录每个客户端当前进程，并在收到中断报文后向对应进程组发送中断或清理进程树。提示符处 Ctrl+C 不退出客户端。 |
| Tab 处理 | Tab 会作为命令字符传递给远端 shell，不在客户端改写为空格；由于当前没有 PTY 和交互式 shell，不实现 SSH 那种远端补全能力。 |
| ANSI 转义序列过滤 | 输入侧会过滤 ANSI 转义序列，避免粘贴控制序列污染命令；输出侧显示前也会过滤 ANSI 转义序列，避免颜色、光标移动等控制序列造成乱码或界面错乱。 |
| 输出方向滑动窗口可靠传输 | 客户端到服务端的命令输入继续使用停等 ARQ；服务端到客户端的命令输出升级为小窗口批量发送，按分片序列号 ACK、超时重传，并在客户端按序缓冲和显示。 |
| 实时命令输出 | 服务端不再等待命令结束后一次性返回输出，而是持续读取子进程 stdout/stderr，读到内容后立即可靠发送给客户端。 |
| 输出编码兼容 | 服务端优先按 UTF-8 解码命令输出；如果检测到非法 UTF-8，再回退到服务端本机编码（Windows 常见 GBK/CP936），最后统一转成 UTF-8 发给客户端，兼容 Windows 普通命令和 UTF-8 文件内容。 |

### 2.2 进阶阶段支持的命令

在基础命令范围上，当前进阶实现额外适合以下场景：

| 场景 | 示例 |
|---|---|
| 持续输出且会刷新 stdout/stderr 的命令 | Windows: `ping -n 5 127.0.0.1`；Linux/macOS: `ping 127.0.0.1` |
| 大批量输出命令 | Windows: `for /L %i in (1,1,1000) do @echo XXXXXXXXXX`；Linux/macOS: `seq 1 1000` |
| 查看文本文件 | Windows: `type README.md`；Linux/macOS: `cat README.md` |
| 输出 ANSI 颜色文本 | Windows/Linux 均可使用 `python -c "print('\033[31mRED_TEXT\033[0m')"`，客户端会显示过滤后的普通文本。 |

限制说明：

- 实时输出传输的是子进程已经写出并 flush 到 stdout/stderr 的内容；部分程序检测到 stdout/stderr 是管道时会自行缓冲，可能仍然延迟显示。
- 当前没有 PTY，因此不支持 `vim`、`top`、交互式 Python、`sudo` 提示输入等需要完整交互终端的程序。
- 当前不实现终端窗口大小同步，也不实现按接收端缓冲区动态调整窗口的流量控制。

## 三、使用方法

### 3.1 启动服务端

```bash
python server.py [端口]
```

默认监听 `0.0.0.0:9999`。例如：

```bash
python server.py 10000
```

也可以指定监听地址：

```bash
python server.py 10000 --host 0.0.0.0
```

### 3.2 启动客户端

```bash
python client.py [服务端IP] [服务端端口]
```

默认连接 `127.0.0.1:9999`。例如：

```bash
python client.py 192.168.1.100 10000
```

客户端启动后会先发送心跳并等待服务端 ACK；如果约 2 秒内没有收到回复，会打印连接失败并直接退出。连接成功后才会显示类似 `[user@host dir]$` 的提示符。

每次命令输出结束后，服务端会发送一个携带当前工作目录的结束标记，客户端收到后自动更新提示符并显示下一条提示符，不需要额外再按一次回车。

客户端中输入 `exit` 可以退出。交互式终端中客户端只把 `exit` 作为主动退出命令；`Ctrl+C` 不用于退出客户端，在提示符处按下时会回到提示符，在命令执行期间按下时会发送远程中断报文并继续等待命令输出结束。Linux/macOS TTY 通常由终端回显 `^C`，客户端只补换行；Windows 或非 TTY 环境由客户端打印 `^C`。

## 五、协议格式

固定头部 13 字节，采用大端字节序，发送端将单个 UDP 报文总长度控制在 1472 字节以内以避免 IP 分片。

| 字段 | 长度 | 说明 |
|---|---:|---|
| 魔数 | 2B | 固定 `0x5554`，用于识别合法报文 |
| 报文类型 | 1B | `0x01` 命令输入，`0x02` 命令输出，`0x03` ACK，`0x04` 心跳，`0x05` 中断 |
| 序列号 | 4B | 用于 ACK、去重、保序和重传 |
| 数据长度 | 2B | 数据段长度 |
| 客户端 ID | 4B | 区分多个客户端 |
| 数据段 | 可变 | 命令内容、输出内容或控制元信息 |

当前实现中，普通命令和输出序列号使用 `0..0xFFFFFFFE` 循环递增，`0xFFFFFFFF` 保留给心跳报文使用。中断报文用于通知服务端中断当前命令，不参与命令序列去重。

## 六、测试说明

运行自动化测试：

```bash
python test_all.py
```

自动化测试和实现验证内容包括：

- 协议封包/解包、魔数校验、类型校验、长度校验、超长数据拒绝。
- 4 字节序列号、ACK、超时重传和重复序列号去重。
- 命令执行、持久 `cd` 目录切换和输出显示。
- 多客户端隔离。
- 心跳 ACK、客户端启动连接判定、提示符元信息同步、服务端心跳日志和离线清理。
- 基础控制字符 `\n`、`\r`、`\b`、`\x7f` 处理。
- Tab 透传、ANSI 转义序列过滤。
- 非 ASCII 输出编码兼容，包括 Windows 普通命令输出和 UTF-8 文件内容输出。
- Windows 下带双引号的 `python -c "..."` 命令执行，验证 shell 引号解析兼容。
- 实时输出首包提前到达。
- 大输出滑动窗口传输完整性。
- 命令不存在、服务端不可达、非法报文不崩溃等异常场景。

自动化测试不模拟交互式终端 Ctrl+C；如需验证远程中断，可手动运行 `ping`、`sleep` 等长命令后按 Ctrl+C。
